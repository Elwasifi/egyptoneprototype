# Architecture

## Monorepo

pnpm workspaces + Turborepo. `apps/web` is the only deployable app today;
`packages/*` are internal libraries consumed via TypeScript path aliases
(`@egypt-one/*` → `packages/*/src`), never published.

```
apps/web            Next.js 15 App Router, [locale] segment, ~74 route templates
packages/types       Shared TypeScript domain/enum types
packages/config      Theme tokens, revenue rules, env
packages/i18n        8-locale message dictionaries + translator
packages/database    Repository layer: DEMO_MODE JSON pack or Prisma/Postgres
packages/ui          Design system: brand, primitives, data viz, layout, media
packages/security    RBAC+ABAC decision engine, audit log, rate limiting
packages/integrations Adapter contracts + null/sandbox implementations
packages/mcp         MCP server/tool registry + enforcement gateway
packages/agents      16-agent registry + orchestrator + source-label guard
packages/skills      Orchestration functions the agents/API call into
```

## Why server logic lives in Next.js route handlers today

The specification calls for a dedicated NestJS backend. In this build phase,
every server-side operation (`/api/search`, `/api/trip/build`,
`/api/ai/concierge`) is implemented as a Next.js Route Handler that calls
directly into `packages/database`, `packages/security`, `packages/mcp`,
`packages/agents` and `packages/skills`. This is a **deliberate, documented
interim decision**, not a silent scope cut:

- All business logic already lives in framework-agnostic packages. None of
  it imports Next.js.
- `apps/api` (NestJS) can be scaffolded to import the same packages and
  expose the same contracts documented in `API_DOCUMENTATION.md` without
  rewriting any domain logic — `infrastructure/docker/Dockerfile.api` is
  already in place for that extraction.
- Doing so was out of scope for this pass given sandbox constraints (no
  network access to fetch NestJS's own toolchain artefacts reliably
  alongside the Next.js build); it is the clearly signposted next step
  rather than a claim that a NestJS service exists today.

## Data flow (typical read)

```
page.tsx (Server Component)
  → @egypt-one/database  db.governorates.bySlug(slug)   [DEMO_MODE JSON | Prisma]
  → source-status attached to every record
  → @egypt-one/ui  SourceBadge / DataClassBadge renders it
```

## Data flow (AI Concierge turn)

```
ConciergePanel → POST /api/ai/concierge
  → packages/agents  route(message)            → pick a specialist, check role/consent
  → packages/mcp     callTool(...)              → declared? allowed? rate-limited? valid input? connected? → audit → execute
  → packages/skills  planEgyptTrip / findGuide / discoverInvestment / ...
  → packages/agents  composeGuard(...)          → force-downgrade the source label if a sensitive topic lacks an authoritative citation
  → ConciergePanel renders content + action cards + citations
```

## Codegen

Rather than hand-writing ~74 near-duplicate route files, four Node scripts
under `scripts/` emit `apps/web/src/app/[locale]/**/page.tsx` from
structured data arrays that read live from `@egypt-one/database`:

| Script | Emits |
|---|---|
| `gen-listings.mjs` | 27 filterable directory routes (governorates, heritage, hotels, guides, …) |
| `gen-details.mjs` | 10 dynamic `[slug]` detail templates |
| `gen-editorial.mjs` | 30 editorial/landing routes (about, invest, safety, ai, map, …) |
| `gen-portals.mjs` | 40 authenticated portal routes across account/provider/partner/government/admin |

Regenerate after changing a script with `node scripts/<name>.mjs`, then
rebuild. Hand-written templates (the homepage, the governorate detail page,
shared components) are not regenerated by these scripts.

## Frontend stack

Next.js 15 App Router, React 19, TypeScript strict mode, Tailwind CSS v4
(CSS-first `@theme`/`@utility` config in `globals.css`, no `tailwind.config.js`).
Every internal package is listed in `next.config.mjs`'s `transpilePackages`.

## Imagery and maps

No stock photography and no mapping vendor are used. `SmartImage`
(`packages/ui/src/media.tsx`) renders a deterministic, seed-hashed SVG
illustration per subject; `EgyptMap` renders a schematic, layered SVG map
projected from a hardcoded Egypt bounding box. Both are designed to be
swapped for a licensed vendor later without changing call sites.
